# 🖼️→📄 图片转 PDF (images_to_pdf.md)

## 触发条件
- **文件类型**: jpg, jpeg, png, webp, bmp, tiff（单张或多张）
- **意图关键词**: 转pdf, 转成pdf, 做成pdf, 合成pdf, 合并成pdf, 生成pdf, 打包成pdf

> 与 `image_stitching.md` 的区别：那份是把多图**拼成一张长图**；
> 本份是把每张图作为**PDF 的一页**。用户说"拼接/长图"用那份，说"转 PDF"用本份。

## 处理逻辑 (ImageMagick)

### 页面尺寸是关键
`convert` 默认把图片像素数直接当作页面点数 —— 一张 2400x3200 的图会生成
**2400x3200 pt（约 33 英寸）** 的页面，横竖混排时每页大小还不一致，
在阅读器里和打印时都不正常。

**默认统一适配为 A4**：150 dpi 下 A4 即 1240x1754 像素，居中留白。
实测 3 张手机照片：原始尺寸出 PDF 252 KB 且页面忽大忽小；A4 适配后 100 KB 且页面一致。

```bash
# 占位符必须替换成任务给定的真实绝对路径，按用户期望的顺序排列
# （任务给出的文件名已带序号前缀，按其顺序即可）
convert <图1绝对路径> <图2绝对路径> -resize 1240x1754 -gravity center -background white -extent 1240x1754 -units PixelsPerInch -density 150 <输出目录>/<原名>.pdf
```

### 保持原始尺寸
用户明确要求"保持原图尺寸/不要留白/按原图比例"时去掉适配参数：

```bash
convert <图1绝对路径> <图2绝对路径> -units PixelsPerInch -density 150 <输出目录>/<原名>.pdf
```

### 体积控制
- JPEG 输入会被原样内嵌，几乎无额外开销，通常无需处理。
- **不要对 PNG 加 `-compress jpeg`**：实测截图类 PNG 反而从 8 KB 涨到 30 KB。
  让 ImageMagick 自行选择压缩方式。
- 产物明显大于输入时流水线会要求重做，此时加 `-quality 75` 或降低 `-resize` 尺寸。
- **页数很多时体积大是正常的**：几十上百张图合成的 PDF 本就不可能很小。
  此时不要为了压体积而过度降质，按合理参数原样输出即可。

## 输出规范
- 产出文件必须保存在任务指定的输出目录中。
- 单张图输入时文件名用 `[原文件名].pdf`；多张合并时用 `merged.pdf`。
- 页序即命令中图片的排列顺序，务必与任务给出的文件列表顺序一致。
